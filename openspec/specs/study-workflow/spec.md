# study-workflow Specification

## Purpose
系统学习与知识沉淀：`/study` 与 `/skill-test` 两个命令驱动的学习闭环，以及 5 类沉淀内容各自的唯一写入地边界，避免信息散落与多处数据打架。
## Requirements
### Requirement: /study 学习闭环
`/study [主题|review|log|项目]` 按固定阶段执行：生词检查 → 完整学习材料 → 知识检测（5-8 题）→ 模拟面试（3-5 轮）→ 写回全部沉淀文件（快照 + 学习记录 + 每日日志 + 技术清单 + 错题本 + 生词本）。

#### Scenario: 完整学习一次
- **WHEN** 用户执行 `/study <主题>` 并完成检测与模拟面试
- **THEN** 评分快照追加到真相源 JSON、报告脚本重跑、学习记录该主题条目由 🟠 更新为 🟡/🟢、待办项从「待学」迁移到「已完成」区、日志追加会话流水

#### Scenario: 中途退出
- **WHEN** 学习材料输出后用户中途退出会话
- **THEN** `docs/学习记录.md` 中已存在该主题的 🟠 学习中条目，下次可接续

### Requirement: 错题强制归档
所有评分 ≤ 40 的技能涉及的错题必须归档到 `docs/错题本.md`，按技术分类追加，字段包含题目/错误答案/正确答案/原因；日志与其他文档只引用「详见错题本 X 类」，不得展开完整错题。

#### Scenario: 测出低分技能
- **WHEN** `/skill-test` 某技能评分 ≤ 40
- **THEN** `docs/错题本.md` 中出现对应分类的新错题条目，否则视为流程未完成

### Requirement: 5 类内容唯一写入地
错题 → 错题本；已学主题档案 → 学习记录（每主题一条、薄弱点仅一句）；会话过程流水 → 每日学习日志；待办/缺口 → 技术学习清单；评分数字 → 能力评估数据 JSON。任一类型内容禁止在其唯一写入地以外的文档展开。

#### Scenario: 写日志
- **WHEN** 一次学习会话结束写 `docs/每日学习日志.md`
- **THEN** 日志含测验结果与评分变更，错题仅以「详见错题本 X 类」引用，不内联完整错题清单

### Requirement: 工作文件模板引导
`/study` `/skill-test` 引用的 `docs/` 工作文件（生词本/错题本等）不存在时，先从 `docs/templates/` 复制同名模板再操作，不得因文件缺失中断。

#### Scenario: 首次使用
- **WHEN** 新 fork 仓库中 `docs/错题本.md` 尚不存在时执行 `/study`
- **THEN** 命令先从 `docs/templates/错题本.md` 复制创建，流程继续

### Requirement: 学习材料粒度规范
学习材料必须满足 12 条粒度规范（先讲解后追问、原理→机理→工业级落地、面试连环追问、ASCII 图、真实业务场景示例、缩写首次出现给全拼等），标准是用户读完后无需追问即可理解透彻并能应对连环追问。

#### Scenario: 材料质检
- **WHEN** 一份学习材料仅罗列术语提纲、无机理讲解即抛面试题
- **THEN** 该材料不符合规范，需按「第一阶段讲解 + 第二阶段追问」结构重写
